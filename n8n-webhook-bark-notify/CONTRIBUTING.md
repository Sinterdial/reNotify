# 贡献指南（Contributing）

欢迎提交 Issue、Bug 修复、文档改进或新增更多自托管应用的通知解析节点！

## 如何新增一个通知来源解析节点

本工作流采用「入口归一化 → 并行解析层 → 统一去重与发送」的松耦合设计，新增应用只需三步：

1. **在「准备请求」节点中识别新来源**：
   在 `detectKind()` 函数中添加特征字段判断，返回唯一的 `kind` 标识（例如 `"uptime_kuma"`）。
2. **新增独立的「解析 - `<应用名>`」Code 节点**：
   - 开头集中声明可配置常量（默认图标、跳转地址等），并附清晰中文注释；
   - 仅当 `item.json.kind === "你的标识"` 时执行解析，否则直接返回空数组 `[]`；
   - 使用统一 `bark(group, title, body, extra)` 结构输出 `{ json: { bark, source, event } }`，并做好 UTF-8 截断保护（标题 <= 240 字节，正文 <= 2800 字节）；
   - 将节点输入连接到 `准备请求`，输出连接到 `通知去重`。
3. **使用脱敏测试样本验证**：
   - 使用 `curl` / PowerShell 或任意 Webhook 调试工具向你的 n8n 发送带 `"__test": true` 的脱敏测试 JSON；
   - 确认返回 HTTP 200、手机端通知排版清晰且无异常报错。

## 提交 Pull Request 前请务必自检

- [ ] **严格脱敏**：确认未包含任何真实域名、内网 IP（`192.168.*` / `10.*`）、Bark Device Key、API Token、账号密码、个人媒体库 ID 或图床私有链接。
- [ ] **同步更新单节点文件**：若改动了某个 Code 节点，请同步导出至 `workflows/nodes/` 对应文件，并保持与 `workflows/webhook-to-bark.json` 一致。
- [ ] **补充文档说明**：若新增了来源或可配置变量，请同步更新 `README.md` 与 `docs/IMPORT_GUIDE.md`。
